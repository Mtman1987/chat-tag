# Quackverse Art Canon

## Source of truth

Quackverse card art is permanent authored game content. AI generation is an admin-only authoring tool used to seed or deliberately replace a card's artwork; it is never a per-view or per-match runtime dependency.

The accepted static image stored for a card is authoritative until an admin intentionally replaces it. Manual uploads remain authoritative overrides.

## Canon hierarchy

Artwork must preserve the card's established identity in this order:

1. **Card identity and lore** — name, abilities/effect, flavor and individual identity.
2. **Family** — related cards share recognizable visual DNA.
3. **Trunk / role** — controls combat silhouette and recognizable function.
4. **Class and subclass** — controls equipment, pose, build and role presentation.
5. **Visual affinity / faction language** — palette, materials and effects.
6. **Species and individual traits** — bill, plumage, body silhouette and anatomy.
7. **Signature equipment** — weapon, focus, armor language and other unique identifiers.

Family/faction/trunk members should look related, not cloned. Shared palette ranges, material language, motifs and VFX should coexist with distinct faces, plumage, poses, silhouettes and signature gear.

Invalid static art includes concept sheets, model sheets, character turnarounds, multiple poses or angles, duplicate characters, reference diagrams, white sketch backgrounds, and accidental crops that cut off the subject's face, bill, limbs, weapon, or core silhouette. These should be regenerated and should not count as approved card art.

`src/lib/quackverse-visual-canon.ts` is the canonical visual metadata source used by the AI prompt builder.

## Static generation

`POST /api/quackverse/art/generate` is admin-only and card-specific.

The route:

- selects only missing cards by default;
- verifies that the physical saved asset exists instead of trusting manifest metadata alone;
- builds a lore-aware prompt from family, trunk/role, class/subclass, species, plumage, armor, signature weapon, palette, VFX, effect and flavor;
- calls StreamWeaver's existing image-generation route;
- saves the returned image permanently under `quackverse-card-art/<cardId>/static.<ext>`;
- records the saved asset in `gameSettings.default.quackverseArt`;
- skips that card in later missing-only runs;
- removes an obsolete prior file only after the replacement image has been written successfully.

A failed card stays missing and is eligible for the next batch. Successful cards are never regenerated by default.

## Batch seeding

The admin manager retains **Fill Next 5 Missing** for watched/manual runs.

The repository also contains `.github/workflows/quackverse-art-seed.yml`. A push to the dedicated `ops/quackverse-art-seed` branch triggers the live Fly app to generate missing static art in sequential batches of five. The workflow stops when all physical static files are present, or stops safely if a batch produces zero successes rather than looping forever.

This gives operators and ChatGPT/GitHub tooling a repeatable way to trigger and monitor the backlog without adding a second generation system.

## StreamWeaver contract

Quackverse uses the existing StreamWeaver `/api/ai/image` route through its MountainView bridge. The request always supplies a stable tenant context, because StreamWeaver requires a tenant even for internal bridge calls.

Returned persisted image URLs may be relative to StreamWeaver. The Quackverse caller resolves them to absolute URLs before downloading and storing the image locally.

The admin manager can choose SeaArt, Eden / Leonardo, or Cloudflare FLUX per test batch so bad provider behavior is easy to compare before scaling beyond five cards. Reference images sent to StreamWeaver must use a trusted public HTTPS ChatTag origin; localhost and internal Fly SSH origins are never forwarded.

Generated assets can be deleted from the manager. Bulk cleanup only removes StreamWeaver-generated files and preserves manual uploads, while selected-card cleanup can remove a specific static or hover slot.

Quackverse image generation hardcodes a `1024x640` / `16:10` card-window composition target. Cloudflare receives that exact request size; Eden and SeaArt receive provider-safe `1024x1024` requests because they can reject non-standard resolutions, while the prompt keeps the complete subject inside the center `16:10` crop with extra environmental bleed.

## Serving artwork

`GET /api/quackverse/art` reports the actual persisted state of every card. A card is counted complete only when both manifest metadata and a non-empty physical file exist.

`GET /api/quackverse/art/file` serves the persisted asset used by the game and admin preview.

The deterministic SVG canon endpoint may remain available as a development/fallback diagnostic, but it is not considered finished production artwork and must not mark cards complete.

## Hover animation

Static AI artwork comes first. Once all static assets are approved, the saved static image becomes the canonical source frame for the existing FFmpeg video/GIF pipeline.

Hover animation is generated once and persisted in the same way as static art. It must never regenerate on hover, page load or gameplay.
